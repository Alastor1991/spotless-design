# Бриф для Claude

Этот файл — рабочий бриф для Claude (и любых других ИИ-ассистентов), который делает дизайн и фронтенд прототипа Spotless. Он читается в начале каждой сессии. Описание проекта для людей — в [README.md](README.md).

**Коротко о роли.** Ты делаешь дизайн-прототип: HTML + React без бэкенда. Он станет эталоном для реализации на Rust + Slint. Владелец проекта — Alastor1991; бэкенд (Go) он будет писать сам, фронтенд и дизайн — твоя зона. Общение — по-русски. Планка качества — «выверять чуть ли не каждый пиксель».

## 1. Быстрый старт

```sh
python3 -m http.server 8765        # из корня репозитория
# прототип: http://localhost:8765/spotless/
```

- Точка входа — `spotless/index.html`. Корневой `index.html` перенаправляет туда, `404.html` ловит старые ссылки (в том числе на прежнее имя `Spotless - десктоп.html`).
- Сборки нет: `.jsx` компилирует Babel прямо в браузере.
- Публичное демо — GitHub Pages из ветки `main`: https://alastor1991.github.io/spotless-design/
- Состояние прототипа живёт в `localStorage["spotless_proto_v1"]`. Чтобы открыть сразу нужный экран без онбординга, положи туда `{"uiVersion":2,"onboarded":true,"route":{"page":"album","id":"grunt"}}`.

## 2. Порядок работы с владельцем

- Владелец гоняет прототип руками — на компьютере (в том числе в тайлинге, на пол-экрана) и на Android-телефоне в приложении Claude (окно около **412×757**). Присылает правки со скриншотами. Каждая мелочь важна.
- **Не переходить к следующему крупному пункту**, пока текущий не доведён полностью.
- **Сначала воспроизвести, потом чинить.** Найти настоящую причину; если проблемы в одном слое повторяются — пересмотреть устройство всего слоя, а не латать симптом (так пересобраны лайк и оценка, см. 6.3 и 10).
- Правки — точечно; после каждой партии — проверка по разделу 9.
- Владелец просил не менять активно уже одобренные тексты: формулировки он утверждает сам. Новые — по правилам раздела 5.
- Решения, которые относятся к вкусу (форма плеера и т. п.), лучше делать **настройкой**, чем решать за пользователя.
- `localStorage` пользователя не сбрасывать: там его настройки и прогресс. Несовместимые изменения — через `uiVersion` и разовую миграцию в `App`.
- **Git**: работа в отдельной ветке; в `main` (оттуда собирается демо) — только по решению владельца. Сообщения коммитов — по-русски, с объяснением «что и почему». Pull request — только по просьбе.
- Отчитываться коротко и честно: что сделано, что проверено и как, что осталось и что решено за владельца (такие решения называть явно).

## 3. Продукт: что нельзя нарушать

Spotless — открытый музыкальный сервис: по функциям — уровень Spotify Premium, по устройству — его противоположность. Подробно — в README.

- **«Обратный столлманизм».** Пользователь не обязан знать про криптовалюту, p2p, смарт-контракты, DHT — в основном интерфейсе этих слов нет. Свобода подаётся как удобство. Знающим — хорошо заметный раздел «Продвинутое» в настройках и тихие приветы (`12 PEERS · DHT OK`, `FLAC 24/96`, `⌘K`).
- **Деньги.**
  - Сумма в месяц — любая ($2 / $5 / $10 / своя) и **ни на что не влияет**, кроме того, сколько получат артисты. Все функции — всем.
  - Деньги делятся пропорционально времени прослушивания и только между теми, кого слушал этот человек.
  - Разовые донаты (трек, альбом, артист) — кнопкой `$`, с баланса.
  - **Комиссия сервиса 0%.** Сетевые издержки показываются до подтверждения; в пути «с карты» — итог к зачислению.
  - Пополнение — два равноправных пути карточками: «С карты» (виджет он-рамп-провайдера, личность подтверждается один раз у партнёра) и «С другого кошелька» (QR, подпись «USDC в сети Solana», «подтверждение личности не понадобится»).
  - **Автосписания нет** — только напоминание раз в месяц. Слово «автосписание» и PayPal как основа в текстах не появляются.
- **Прозрачность артистов**: строка «Получает в среднем $X с одного слушателя · $Y за последний месяц» и «Откуда эта цифра?»; артист может скрыть месячную сумму.
- **Вход**: через Google (ключ хранится в Google-аккаунте пользователя) или по фразе-ключу; оба пути на одном экране.
- **Название** Spotless: «безупречный» и *Spot-less*, «без Спота». Утверждено.

## 4. Дизайн

### 4.1. Направления

| Платформа | Направление | Статус |
|---|---|---|
| Компьютер и Android | **«Точка»** — в духе последних версий Nothing OS | основа прототипа |
| iPhone | **Liquid Glass «с подходом Дурова»** (как Telegram для iOS): стекло только у плавающих элементов, контент плоский и читаемый | концепт-макеты, не реализовано |
| — | «Упрощённый Spotify» | отклонён |

Почему переделывали: первая версия выглядела как стандартный Material 3 — однотипно и дёшево («что угодно, но не Spotify»). Дизайн должен цеплять уже на скриншотах в README и в рекламе.

### 4.2. Принципы «Точки»

- Чёрный фон, **белое главное действие** (кнопка «Слушать», выбранный чип, активный пункт).
- **Один горячий цвет со смыслом**: `--hot` (в «Точке» — красный, в других палитрах — их фирменный цвет) — только «сейчас играет», лайк, живое, непрочитанное, доп. донаты в истории. Декоративного горячего цвета нет.
- **Точечная матрица**: цифры — шрифт Doto (`DotTime`, суммы); прогресс, громкость, распределение денег — `DotBar` (всегда целое число точек); обложка в полном экране может быть «точками» (маска `.glyph`).
- **Типографика**: Geist Light — крупные заголовки, Geist — текст, Geist Mono капсом с разрядкой — подписи (`.mlabel`). Навигация пронумерована (`01 Главная`), активный пункт — красная точка.
- Скругления 28px у виджетов, тонкие линии вместо теней.
- **Генеративные обложки** (`Cover`, `ALBUM_ART`, `ARTIST_ART`): у альбомов и артистов — свои CSS-картинки, у плейлистов — точечный узор в их цвете. Не заменять на SVG-арт; при выходе будут настоящие.

### 4.3. Токены

Цвета и шрифты — **только через CSS-переменные**, в компонентах никаких литералов цвета (исключение — текст поверх затемнённой обложки). Переменные станут глобалами тем в Slint.

| Токен | «Точка» | Назначение |
|---|---|---|
| `--bg0` … `--bg3` | `#000` `#0A0A0A` `#121212` `#262626` | фон и уровни |
| `--line` | `#1C1C1C` | разделители |
| `--text` / `--mut` / `--mut2` | `#F2F2F2` / `#A3A3A3` / `#8A8A8A` | текст |
| `--acc` / `--acc-ink` | `#F2F2F2` / `#000` | главное действие |
| `--hot` / `--hot-ink` | `#D71921` / `#FFF` | «сейчас», лайк; текст и значок на нём |
| `--bad` | `#FF5A4E` | оценки 1–4 |
| `--dot-off` | `#2A2A2A` | погашенная точка |
| `--dot-l` | `0.8` | светлота цветных точек в обложках плейлистов и плитках жанров |
| `--island` | `#111` | поверхности: плеер, виджеты, поповеры, окна |
| `--island-shadow` / `--shadow` / `--scrim` | | тень плеера, тень поповеров, затемнение под окнами |
| `--cover-l1` / `--cover-l2` | `0.30` / `0.25` | светлота обложек-заглушек |
| `--font` / `--mono` / `--font-dot` | Geist / Geist Mono / Doto | общие для всех тем |
| `--r` / `--r-sm` | 28px / 14px | общие для всех тем |

Шрифты и скругления заданы один раз в `:root`. Каждая палитра (`:root, [data-theme="dot"]` и шесть остальных) задаёт **полный** набор цветовых токенов. Правила компонентов пишутся без привязки к теме (`[data-theme] .x` или просто `.x`) — условий «если тема такая-то» в CSS и JS нет.

**Классы состояний** — с префиксом `is-*` (`is-on`, `is-bad`) или явным именем (`just-liked`). Никогда не использовать в роли состояния общие слова, у которых есть глобальное правило (`pop`, `on`, `active`…). Перед добавлением нового класса проверить, нет ли самостоятельного правила с таким именем (см. 10).

### 4.4. Кастомизация

Путь: **одна вылизанная основа, потом настройки поверх неё** (а не несколько полностью разных стилей). Темы — **только цветовые палитры** одного дизайна: шрифты, скругления, компоненты и подписи у всех одинаковые. Логика цвета везде одна: главное действие — цвета текста (`--acc`), фирменный цвет палитры — горячий (`--hot`).

| Палитра | id | Фон | Горячий цвет |
|---|---|---|---|
| Точка (по умолчанию) | `dot` | чёрный | красный |
| Тёплая ночь | `dark-warm` | тёплый графит | жёлтый |
| Студия | `dark-neutral` | холодный графит | жёлтый |
| Глубина | `dark-sea` | тёплый графит | голубой |
| Солнечная | `light-cream` | кремовый | янтарный |
| Бумага | `light-neutral` | белый | красный (светлая «Точка») |
| Зефир | `light-rose` | розоватый | малиновый |

Новые палитры проверять по контрасту: текст ≥ 7:1, приглушённый ≥ 4,5:1, горячий цвет на фоне ≥ 3:1 (значки). Отличия шрифтами и скруглениями владелец пока выдавать не хочет.

Ещё настраивается: акцент (подменяет `--hot` в любой палитре), обои, плотность, форма плеера, оценка быстрого лайка; галерея тем, экспорт и импорт JSON. В текстах не обещать «настраивается всё, вплоть до мелочей» — называть конкретно, что меняется.

### 4.5. Контент-вселенная

Молоко и мёд (Казань, инди), Low Tide Choir (Брайтон, dream-pop), Velvet Antenna (synthwave, скрывает доходы), Paper Planes Club (Лиссабон, инди-рок), Танец Бруно (Москва, электроника), Грунтовка (Пермь, пост-панк). Пользователь — Лиза, $5 в месяц. Всё выдумано.

## 5. Язык интерфейса

Русский должен читаться естественно для носителя.

- **Тон**: сдержанно-приветливый, тёплый, без сюсюканья и канцелярита.
- **«Медиатека»**, не «Библиотека».
- **Не называть раздел «Поддержка»**: в российских приложениях (VK, «Мой МТС», Яндекс, Boosty, Apple) это служба поддержки. Раздел с деньгами — **«Артистам»**, заголовок — «Кому идут ваши деньги». Глагол «Поддержать» на кнопках — норма (VK Донат, Boosty, Дзен).
- **Без безглагольных калек**, где подлежащее — существительное, а глагола нет: «Поддержка в июне», «Моя поддержка артисту», «пополнение — в два касания». Переписывать через глагол: «Кому идут ваши деньги в июне», «пополнить можно в два касания». Метки над числами («Артистов в июне», «Комиссия сервиса») — нормальная форма.
- **Новые формулировки такого рода сверять с русскоязычными источниками**: словари (Ожегов, Ушаков, Розенталь, Грамота.ру), реальные российские сервисы. Пример: «1 поддержка» — ошибка (в значении помощи только ед. ч., Ушаков); «поддержка артисту» — дательный при самом существительном нормален только в значении «опора» (Розенталь), в «оказать поддержку кому» он у глагола.
- **Чуть более длинная естественная фраза лучше рубленой.**
- **«Комиссия сервиса 0%»** — ровно так.
- Деньги в RU — с запятой: `fmtMoney(n, lang)` → `$1,90`. Числительные склонять («и ещё 2 артиста»).
- Названия треков и артистов не переводить. Все строки — в `js/i18n.js`, RU и EN.

## 6. Функции и принятые решения

### 6.1. Что есть

Онбординг (манифест → вход Google или фраза-ключ → тема → сумма → три карточки); Главная (виджеты «Вы остановились здесь», «Кому идут ваши деньги в июне», «Что слушают друзья»; ряды); Поиск; Медиатека; Альбом; Артист; Плейлист, Любимые треки, «Показать все», Жанр; Профиль, Jam; «Артистам» (сумма, пополнение, баланс, распределение точками, история); Настройки (Внешний вид, Воспроизведение и загрузки, Оценки, Язык и регион, Подсказки, Аккаунт, Продвинутое); плеер-островок / скруглённый / панель; полный экран; правая панель и очередь; мини-плеер; контекстные меню; уведомления; устройства; донат; загрузки; RU/EN.

Заглушки: «Подробные карточки-инструкции» (ведут в онбординг), «Открыть конфиг» (уведомление), подкасты.

### 6.2. Телефон (Android, ≤640px)

Отдельная раскладка: нижняя навигация (Главная, Поиск, Медиатека, Артистам; повторный тап — наверх, память прокрутки по вкладкам), шапка с логотипом или «Назад» и заголовком страницы при прокрутке (+ маленькая «Слушать»), мини-плеер (капсула или панель; тап — развернуть, свайп вбок — трек, вверх — развернуть; прогресс в капсуле только индикатор), полный экран (обложка/точки, текст и очередь на месте обложки, смахнуть вниз — свернуть, свайп по обложке — трек), строки треков (состояние + «⋯», тап играет, долгое нажатие — меню), нижние листы с ручкой, отклик на нажатие и вибрация.

### 6.3. Лайк и оценка

**Лайк — это оценка.** Источник правды — `rating`: 1–10 или `null`.

- 5–10 — в любимых (сердечко закрашено); 1–4 — «не нравится» (зачёркнуто, `--bad`); `null` — не оценивали.
- Тап по пустому — `likeRating` (настройка «Оценки», 5–10, по умолчанию 10). Тап по горящему — снять; для осознанной оценки (≠ `likeRating`) в тосте «Вернуть».
- Удержание (350 мс) — окно шкалы; не отпуская палец, можно вести: значение и крупная цифра меняются на ходу, отпускание ставит. Без движения (порог 10px) окно остаётся.
- Окно **само не закрывается**: тап мимо, чёрточка сверху, Esc. «Убрать оценку» = `null`.
- В полном экране и в панели плеера шкала встроена (`RateScale variant="inline"`).
- Цифра у сердечка — только для оценки ≠ `likeRating`.
- Лайк без числа (данные из базы, старые сохранения) читается как `likeRating`.

### 6.4. Не меняется без обсуждения

- Сердечко и плюсик — **разные** кнопки.
- Лайк — это оценка (6.3).
- Кнопки в строке трека на компьютере — по наведению, лайк и «скачано» видны всегда; порядок ♥ · ＋ · ⭳ · $. На телефоне — состояние и «⋯».
- Умное перемешивание — третий режим кнопки + уведомление.
- «Медиатека»; раздел «Артистам».
- Форма плеера — настройка.
- Подкасты вторичны.
- Валюта — $ по умолчанию, меняется один раз и запоминается.
- Пополнение — два пути карточками; никакого «автосписания».

## 7. Устройство кода

### 7.1. Стек

- React 18.3.1 UMD + Babel standalone в браузере. Версии и `integrity` в тегах скриптов не менять.
- Каждый `.jsx` — отдельный `<script type="text/babel">`; общие компоненты отдаются через `Object.assign(window, {...})`.
- Один `css/app.css`: переменные, container queries, без Tailwind.
- Один корневой `App` + контекст `AppCtx` / `useApp()`; всё API приложения — в объекте `api` в `app.jsx`.
- Код должен работать **и без Babel** (живая сборка, раздел 8): `const` до объявления — ошибка.

```
  js/app.jsx                  ← App (состояние и api), Sidebar, TopBar, MobileNav
docs/screens/                 ← скриншоты для README
lib/, Стилевые направления.html ← история первых направлений, не трогать
```

### 7.3. Раскладки и адаптив

- **Телефон**: `useMedia(PHONE_Q)`, `PHONE_Q = "(max-width: 640px)"`. Сайдбар и правая панель не рендерятся; `MobilePlayer` + `MobileNav`; `FullScreenPhone` вместо `FullScreen` (отдельные компоненты — порядок хуков не прыгает). Класс `.shell.phone`, при панели — `.mp-docked`.
- **Компьютер, экстремальное сжатие**: правая панель прячется первой (≤1300px); сайдбар — рейл кнопкой или сам (<1180px); островок — контейнер-запросы, центр `clamp(150px, 40cqi, 460px)`, ступени скрытия: громкость ≤1080 → лайк/плюс/$ ≤980 → текст/устройства ≤790 → перемешивание/повтор/очередь ≤545 → время и название ≤400 → prev/next ≤330; панель плеера — свои ступени. Ступени с `!important` (inline-стили иначе перебивают).
- **Короткие экраны телефона**: `.fsp-stage` с `container-type: size`, обложка `max(120px, min(100cqw, 100cqh - 52px))`; ≤800px по высоте прячется строка текста песни, ≤660px — строка о доле; ≤380px по ширине кнопка доната сжимается до `$`. Онбординг — `.ob` из трёх зон в потоке.
- **Плотность** — `data-density="c|n|s"` на `<html>`; правила в конце `app.css`.

### 7.4. Состояние

- `localStorage["spotless_proto_v1"]`, внутри `uiVersion: 2` (старые сохранения один раз переводятся на «Точку»).
- `settings`: `island` (`pill` | `square` | `panel`), `density` (`c` | `n` | `s`), `accent`, `wallpaper` / `wallpaperImg`, `likeRating`.
- `trackStates[id] = { rating, liked, playlists }`: читать **только** через `trackState(id)`, менять **только** через `setRating` / `toggleLike` / `patchTrack`. Обновления функциональные: `stateFrom(all, id)` считает из снимка, а не из замыкания.
- Тосты: `toast(msg, action?)`, где `action = { label, run }` — такой тост живёт дольше и показывает кнопку.

### 7.5. События и жесты

1. **Поверхность с жестами сама распознаёт тап** (сдвиг < `SLOP` = 10px) и не полагается на всплывающий `click` от детей.
2. **Элементы управления внутри поверхности исключаются по цели**: `e.target.closest("button, [role=slider], .dotbar.seek")`.
3. **Долгое нажатие** — `useLongPress`: только палец, сдвиг > `SLOP` — прокрутка, следующий клик после срабатывания гасится; на сенсорных устройствах нативный `contextmenu` гасится (`isTouchUI()`).
4. **Окна над прокручиваемым контентом** — портал в `body` + граница событий на корне (`stopPropagation` на pointer- и click-событиях): события портала всплывают по дереву React.
5. **«Клик мимо»** — слушатель на `window` в фазе перехвата (`addEventListener(..., true)`); исключать сам поповер и якорь.
6. **Сердечко** — машина состояний `press → armed → scrub` с `setPointerCapture`; шкала — общий `RateScale` (палец, мышь, клавиатура, `onPreview` для живой цифры).
7. Элементы с жестами — `touch-action: none`; списки внутри — `pan-y`; прокрутка — `overscroll-behavior: contain`.
8. Перед жестом, двигающим элемент с анимацией появления, снять анимацию: `el.style.animation = "none"`.
9. Вибрация — `buzz(ms)`, молча ничего, если нельзя.

## 8. Живая сборка для артефакта

Владелец удобнее всего тестирует на телефоне через артефакт Claude. Просмотрщик артефактов ставит свой `data-theme` на корень и требует скриптов с разрешённых CDN, поэтому:

1. JSX компилируется заранее esbuild-ом (`--loader=jsx --jsx=transform --target=es2020`, вход через stdin) в обычные `.js`, порядок файлов как в `spotless/index.html`.
2. `data-theme` в CSS и JS переименовывается в `data-sp-theme`.
3. Страница артефакта — без `<!doctype>/<html>/<head>/<body>` (их добавит публикация): `<title>`, ссылка на Google Fonts (как в `spotless/index.html`), `css/app.css`, `<div id="root">`, React и ReactDOM 18.3.1 production с cdnjs, затем скрипты.
4. Публикация — многофайловым артефактом (`files`: `css/app.css`, `js/*.js`), повторная публикация — тот же путь файла, ссылка сохраняется.
5. После сборки — те же проверки (раздел 9) на собранной версии.

```sh
mkdir -p out/js out/css
for f in ui player pages-home pages-album pages-playlist pages-social pages-support pages-settings menus onboarding app; do
  npx esbuild --loader=jsx --jsx=transform --target=es2020 < spotless/js/$f.jsx | sed 's/data-theme/data-sp-theme/g' > out/js/$f.js
done
cp spotless/js/data.js spotless/js/i18n.js out/js/
sed 's/data-theme/data-sp-theme/g' spotless/css/app.css > out/css/app.css
```

## 9. Проверка

Каждая партия изменений — в Chromium через Playwright (Chromium предустановлен, `playwright install` не нужен), без ошибок в консоли:

- **Размеры**: компьютер 1440×900, 1280×800, 1000×800, 700×800; телефон 412×915, **412×757**, 360×640.
- **Касания — настоящие** touch-события через CDP: `cdp.send('Input.dispatchTouchEvent', { type: 'touchStart' | 'touchMove' | 'touchEnd', touchPoints })`. Клики мышью не ловят ошибки жестов.
- **Лайк и оценка (обязательно)**: быстрый тап ставит `likeRating` и не разворачивает мини-плеер; кнопка не прыгает; удержание с дрожанием 3px не ставит оценку и не закрывает окно; ведение меняет крупную цифру на ходу; тап по точкам ставит и правит, окно не закрывается само; чёрточка и тап мимо закрывают; «Убрать оценку» гасит сердечко; тап по горящему снимает, «Вернуть» возвращает; `likeRating: 7` → тап ставит 7; на компьютере — удержание мышью, клик по точке, правый клик по строке.
- **Жесты**: свайпы мини-плеера, смахивание полного экрана и листов, долгое нажатие на строке (строка должна быть в видимой области — мини-плеер перекрывает низ), заголовок в шапке при прокрутке.
- Одна из старых тем (например, «Солнечная») не сломана.
- На настоящем телефоне последнее слово за владельцем: эмуляция не передаёт ощущение жестов и вибрации.

## 10. Грабли

- **Класс состояния совпал с глобальным.** Сердечку добавлялся `pop` для анимации, а `.pop` — стиль поповеров (absolute, фон, рамка). Кнопка становилась «квадратиком» и сдвигалась, палец оказывался над названием трека, клик разворачивал плеер.
- **Дрожание пальца считалось жестом**: отпускание после удержания ставило оценку по координате сердечка. Нужен порог.
- **Две переменные для одного смысла** (`liked` и `rating` отдельно): тап менял одно, сердечко горело от другого. Один источник правды.
- **Окно, которое закрывается само** через секунду после выбора, мешало поправить оценку. Закрытие — только действием человека.
- **React `stopPropagation` гасит и нативное всплытие** до `window` → слушать в фазе перехвата.
- **События портала всплывают по дереву React** → граница событий на корне портала.
- **`position: fixed` внутри элемента с `transform`** (в том числе оставшимся от анимации с `fill-mode: both`) позиционируется от него → портал.
- **Анимация с `fill-mode: both` перебивает inline `transform`** → снимать анимацию перед жестом; поповеры сдвигать через `left`.
- **Inline-стили перебивают media- и container-правила** → `!important` в ступенях; не ставить inline `display`/`min-width` на то, чем управляет CSS.
- **Обращение к состоянию до объявления** (`queue`, `notifRead`, `hints` в эффекте сохранения): Babel прятал ошибку, скомпилированная сборка падала.
- **Тонкая полоса перемотки по центру капсулы** перехватывала свайпы → в капсуле только индикатор.
- **Цель клика после сдвига раскладки**: если элемент под пальцем сдвинулся между pointerup и click, клик уходит соседу.
- **Обрезанная половинка точки** в конце полосы → ширина полосы — целое число шагов.
- **Doto**: двоеточие при 900 некрасивое → `font-variation-settings: 'ROND' 100`, двоеточие в `DotTime` своими точками; кириллицы в Doto нет.
- **Поповер с замером позиции** монтировать только при открытии.
- **Компоненты, объявленные внутри рендера**, перемонтируются и мигают → всё на верхнем уровне модуля.
- **Тикающий прогресс ререндерит дерево** → тяжёлые поддеревья не должны зависеть от `player.pct`.
- **Контейнер тостов с `left: 50%` + `translateX(-50%)`** ограничен половиной ширины экрана — текст переносился. Контейнер во всю ширину, тосты по центру.

## 11. Будущая реализация и право

Контекст для текстов: экраны и формулировки не должны этому противоречить. В прототипе ничего из этого не кодится.

- **Клиент** — Rust + **Slint** (декларативная разметка переносит CSS-переменные тем в Slint-глобалы почти один в один, API стабилен с 1.0; GPL-вариант совместим с AGPL). Стек мобильных клиентов окончательно не выбран. **Telegram Mini Apps отменены.**
- **Ядро**: rust-libp2p, symphonia + cpal, некастодиальный кошелёк, проверка чанков, локальная база.
- **Инфраструктура** — Go (пишет владелец): bootstrap/relay-ноды, индексатор каталога, кабинет артиста. Контент на серверах не хранится.
- **Деньги** — Solana, контракты Rust / Anchor, актив **USDC**; распределение — накопление в контракте и выплаты пачками; комиссию сети платит fee payer, слово «газ» пользователь не видит.
- **Фиат** — он-рамп-провайдеры (Onramper или MoonPay / Ramp / Mercuryo), Apple Pay, Google Pay, карта, SEPA; KYC у провайдера, один раз; подписочного API нет → напоминание.
- **Право**: архитектура строго некастодиальная (проект не держит ключи и средства) — вне CASP по MiCA и money transmitter по FinCEN, пока это так; любая «централизованная» функция проверяется на этот инвариант. KYC только на границах фиат ↔ крипта у лицензированных провайдеров. В текстах — никаких обещаний из области права («анонимно», «никогда не потребуют»), только факты про наш интерфейс («не понадобится»).
