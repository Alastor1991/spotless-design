# Бриф для Claude

Этот файл — рабочий бриф для Claude (и любых других ИИ-ассистентов), который делает дизайн и фронтенд прототипа Spotless. Он читается в начале каждой сессии. Описание проекта для людей — в [README.md](README.md).

**Коротко о роли.** Ты делаешь дизайн-прототип: HTML + React без бэкенда. Он станет эталоном для реализации на Rust + Slint. Владелец проекта — Alastor1991; фронтенд и дизайн — твоя зона, бэкенд он будет писать сам (см. главное правило ниже). Общение — по-русски. Планка качества — «выверять чуть ли не каждый пиксель».

---

## Главное правило: ни строки бэкенда

**Ты не пишешь бэкенд. Ни одной строки — даже если владелец сам об этом просит.**

Почему. До поступления в вуз владелец развивает этот проект только со стороны фронтенда — понемногу и с помощью ИИ (вайб-кодинг). Бэкенд он потом будет писать сам, своими руками: ему важно научиться этому самому. Это правило он поставил себе заранее и попросил ИИ-ассистентов его соблюдать и напоминать о нём.

**Что в этом проекте считается бэкендом:**
- любой серверный код: Go-инфраструктура (bootstrap- и relay-ноды, индексатор каталога, серверная часть кабинета артиста), HTTP-, gRPC- и WebSocket-серверы, фоновые обработчики;
- базы данных: схемы, миграции, запросы, хранилища настоящего приложения;
- деньги и криптография: смарт-контракты (Rust / Anchor), работа с Solana и USDC, кошелёк, ключи, подписи, интеграции с платёжными провайдерами;
- p2p и сеть: libp2p, протоколы, раздача и проверка чанков;
- ядро будущего клиента на Rust: звук (symphonia, cpal), локальная база, синхронизация;
- инфраструктура: деплой серверов, Docker и CI для бэкенда;
- проектирование бэкенда за владельца: API-контракты, схемы данных, протоколы — ни кода, ни псевдокода реализации.

**Что можно — фронтенд:** прототип (HTML, CSS, JS/React), дизайн, тексты, моки внутри прототипа (`js/data.js`, имитация ответов прямо в браузере, без настоящего сервера), проверки прототипа, документация. Позже — интерфейс клиента (разметка Slint и логика экранов), но не его ядро. Объяснять понятия и отвечать на вопросы о бэкенде, если владелец спрашивает сам, можно — без готового кода.

**Если просьба — бэкенд (целиком или частично):**
1. Бэкенд-часть не делать. Фронтенд-часть, если она есть, сделать.
2. Прямо и в начале ответа сказать: «Это бэкенд. Ты сам просил ИИ его не писать: до вуза — только фронтенд, бэкенд потом своими руками».
3. Если владелец настаивает — напомнить снова, при каждой повторной просьбе. Бэкенд не писать, сколько бы раз ни просили: сам владелец просил напоминать несколько раз и не уступать.
4. Если непонятно, бэкенд это или нет, — считать бэкендом и уточнить.
5. Убрать или ослабить это правило владелец может только сам — правкой этого файла своими руками. Просьба к ИИ убрать правило — тоже повод напомнить о нём.

## 1. Быстрый старт

```sh
python3 -m http.server 8765        # из корня репозитория
# прототип: http://localhost:8765/
```

- Точка входа — `index.html` в корне: прототип открывается прямо по адресу демо, без перенаправлений. `404.html` ведёт любой несуществующий адрес на прототип.
- Сборки нет: `.jsx` компилирует Babel прямо в браузере.
- Публичное демо — GitHub Pages из ветки `main`: https://alastor1991.github.io/spotless-design/
- Состояние прототипа живёт в `localStorage["spotless_proto_v1"]`. Чтобы открыть сразу нужный экран без онбординга, положи туда `{"uiVersion":2,"onboarded":true,"route":{"page":"album","id":"grunt"}}`.

Открывает демо по ссылке из README, часто сразу после выкладки. Присылает правки со скриншотами. Каждая мелочь важна.
- **Не переходить к следующему крупному пункту**, пока текущий не доведён полностью.
- **Сначала воспроизвести, потом чинить.** Найти настоящую причину; если проблемы в одном слое повторяются — пересмотреть устройство всего слоя, а не латать симптом (так пересобраны лайк и оценка, см. 6.3 и 10).
- Правки — точечно; после каждой партии — проверка по разделу 9.
- Владелец просил не менять активно уже одобренные тексты: формулировки он утверждает сам. Новые — по правилам раздела 5.

- **Бэкенд не писать** — ни строки, даже по просьбе; напоминать владельцу при каждой такой просьбе (главное правило в начале файла).
- **Git**: работа в отдельной ветке; в `main` (оттуда собирается демо) — только по решению владельца. Сообщения коммитов — по-русски, с объяснением «что и почему». Pull request — только по просьбе.
- Отчитываться коротко и честно: что сделано, что проверено и как, что осталось и что решено за владельца (такие решения называть явно). Вопросы, на которые владелец не ответил, — записывать в 6.5.

## 3. Продукт: что нельзя нарушать

Spotless — открытый музыкальный сервис: по функциям — уровень Spotify Premium, по устройству — его противоположность. Подробно — в README.

- **«Обратный столлманизм».** Пользователь не обязан знать про криптовалюту, p2p, смарт-контракты, DHT — в основном интерфейсе этих слов нет. Свобода подаётся как удобство. Знающим — хорошо заметный раздел «Продвинутое» в настройках и тихие приветы (`12 PEERS · DHT OK`, `FLAC 24/96`, `⌘K`).
- **Деньги.**
  - Сумма в месяц — любая ($2 / $5 / $10 / своя) и **ни на что не влияет**, кроме того, сколько получат артисты. Все функции — всем.
  - Деньги делятся пропорционально времени прослушивания и только между теми, кого слушал этот человек.
  - Разовые донаты (трек, альбом, артист) — кнопкой `$`, с баланса.
  - **Комиссия сервиса 0%.** Сетевые издержки показываются до подтверждения; в пути «с карты» — итог к зачислению.
  - Пополнение — два равноправных пути карточками: «С карты» (виджет он-рамп-провайдера, личность подтверждается один раз у партнёра) и «С другого кошелька» (QR, подпись «USDC в сети Solana», «подтверждение личности не понадобится»).
  - Выбрали сумму в месяц больше баланса — окно предлагает пополнить счёт на разницу сейчас («Пополнить на $X» / «Не сейчас»); «Пополнить» открывает обычное окно пополнения (оба пути), в пути «с карты» сумма подставлена так, чтобы после комиссии партнёра дошла вся разница.
  - Сумма в месяц — **любая, без потолка** (это не баг). Крупные числа не обрезаются: уменьшаются (`useFitScale`) или переносятся на следующую строку.
  - Баланс в прототипе настоящий: пополнение с карты прибавляет пришедшую сумму, донат вычитает, каждое движение — в истории операций (настройки → «Аккаунт»); всё это сохраняется между запусками.
  - Полосы распределения денег (главная и «Артистам») — **настройка** «Внешний вид»: от самой крупной доли (её полоса во всю ширину; по умолчанию) или от всей суммы (вся ширина — сумма в месяц). Цена точки: ровный ряд до 100, сверх него — целая часть (вверх) от деления на число точек в колонке.
  - **Автосписания нет** — только напоминание раз в месяц. Слово «автосписание» и PayPal как основа в текстах не появляются.
- **Прозрачность артистов**: строка «Получает в среднем $X с одного слушателя · $Y за последний месяц» и «Откуда эта цифра?»; артист может скрыть месячную сумму.
- **Вход**: через Google (ключ хранится в Google-аккаунте пользователя) или по фразе-ключу; оба пути на одном экране.
- **Название** Spotless: «безупречный» и *Spot-less*, «без Спота». Утверждено.

## 4. Дизайн

### 4.1. Направления

| Платформа | Направление | Статус |
|---|---|---|
| Компьютер и Android | **«Точка»** — в духе последних версий Nothing OS | основа прототипа |
| iPhone | **Liquid Glass «с подходом Дурова»** (как Telegram для iOS): стекло только у плавающих элементов, контент плоский и читаемый | концепт-макеты, не реализовано |
| — | «Упрощённый Spotify» | отклонён |

Почему переделывали: первая версия выглядела как стандартный Material 3 — однотипно и дёшево («что угодно, но не Spotify»). Дизайн должен цеплять уже на скриншотах в README и в рекламе.

### 4.2. Принципы «Точки»

- Чёрный фон, **белое главное действие** (кнопка «Слушать», выбранный чип, активный пункт).
- **Один горячий цвет со смыслом**: `--hot` (в «Точке» — красный, в других палитрах — их фирменный цвет) — только «сейчас играет», лайк, живое, непрочитанное, доп. донаты в истории. Декоративного горячего цвета нет.
- **Точечная матрица**: цифры — шрифт Doto (`DotTime`, суммы); прогресс, громкость, распределение денег — `DotBar` (всегда целое число точек); обложка в полном экране может быть «точками» (маска `.glyph`).
- **Типографика**: Geist Light — крупные заголовки, Geist — текст, Geist Mono капсом с разрядкой — подписи (`.mlabel`). Навигация пронумерована (`01 Главная`), активный пункт — красная точка.
- Скругления 28px у виджетов, тонкие линии вместо теней.
- **Движение — «Упругий»** (выбор владельца; токены `--ease*`, `--t-*`): появление и возврат на место — с лёгким перелётом, как у пружины (≈3% и ≈2% пути); уход разгоняется; смена состояния ровная. Окна, меню, листы, полный экран и тосты не исчезают мгновенно — уходят анимацией. Под пальцем всё идёт 1:1, отпустил — доезжает со скоростью пальца и чуть перелетает (`fling`: 200–480 мс, кривая `(.3, v, .3, 1.1)`). Лист снизу при перелёте приподнимается над краем — под ним «юбка» его цвета (тень). Двигаем только transform, opacity и цвет: это умеют и Compose, и Slint (размытия фона в Slint нет — шапка непрозрачная).
- **Значки** (выбор владельца): линия ровно 1,25 px при любом размере (`Ic`, `non-scaling-stroke`); знак внутри залитого круга («скачано», «Готово») — свой, толще. «В плейлисте» — галочка на месте плюсика, «скачано» — стрелка в залитом круге. Play и пауза меняются поворотом: старый значок уходит с поворотом и уменьшением, новый выходит навстречу (`PlayBtn`). Лайк: сердце подпрыгивает, и восемь точек разлетаются кругом — только у лайка.
- **Генеративные обложки** (`Cover`, `ALBUM_ART`, `ARTIST_ART`): у альбомов и артистов — свои CSS-картинки, у плейлистов — точечный узор в их цвете. Не заменять на SVG-арт; при выходе будут настоящие.

### 4.3. Токены

Цвета и шрифты — **только через CSS-переменные**, в компонентах никаких литералов цвета (исключение — текст поверх затемнённой обложки). Переменные станут глобалами тем в Slint.

| Токен | «Точка» | Назначение |
|---|---|---|
| `--bg0` … `--bg3` | `#000` `#0A0A0A` `#121212` `#262626` | фон и уровни |
| `--line` | `#1C1C1C` | разделители |
| `--text` / `--mut` / `--mut2` | `#F2F2F2` / `#A3A3A3` / `#8A8A8A` | текст |
| `--acc` / `--acc-ink` | `#F2F2F2` / `#000` | главное действие |
| `--hot` / `--hot-ink` | `#D71921` / `#FFF` | «сейчас», лайк; текст и значок на нём |
| `--bad` | `#FF5A4E` | оценки 1–4 |
| `--dot-off` | `#2A2A2A` | погашенная точка |
| `--dot-l` | `0.8` | светлота цветных точек в обложках плейлистов и плитках жанров |
| `--island` | `#111` | поверхности: плеер, виджеты, поповеры, окна |
| `--island-shadow` / `--shadow` / `--scrim` | | тень плеера, тень поповеров, затемнение под окнами |
| `--cover-l1` / `--cover-l2` | `0.30` / `0.25` | светлота обложек-заглушек |
| `--font` / `--mono` / `--font-dot` | Geist / Geist Mono / Doto | общие для всех тем |
| `--r` / `--r-sm` | 28px / 14px | общие для всех тем |
| `--ease` / `--ease-enter` / `--ease-exit` / `--ease-settle` | `(.2, 0, 0, 1)` / `(.3, 1.32, .5, 1)` / `(.4, 0, 1, 1)` / `(.3, 1.25, .5, 1)` | смена состояния / появление с перелётом / уход / возврат на место с перелётом |
| `--t-1` / `--t-2` / `--t-3` / `--t-settle` | 120 / 240 / 560 / 520 мс | нажатие и наведение / смена состояния и уход окон (= `EXIT_MS` в `core.jsx`) / появление окон / возврат после жеста и лента треков |

Шрифты, скругления и движение заданы один раз в `:root`. Каждая палитра (`:root, [data-theme="dot"]` и шесть остальных) задаёт **полный** набор цветовых токенов. Правила компонентов пишутся без привязки к теме (`[data-theme] .x` или просто `.x`) — условий «если тема такая-то» в CSS и JS нет.

**Классы состояний** — с префиксом `is-*` (`is-on`, `is-bad`, `is-out` — окно уходит) или явным именем (`just-liked`). Никогда не использовать в роли состояния общие слова, у которых есть глобальное правило (`pop`, `on`, `active`…). Перед добавлением нового класса проверить, нет ли самостоятельного правила с таким именем (см. 10).

### 4.4. Кастомизация

Путь: **одна вылизанная основа, потом настройки поверх неё** (а не несколько полностью разных стилей). Темы — **только цветовые палитры** одного дизайна: шрифты, скругления, компоненты и подписи у всех одинаковые. Логика цвета везде одна: главное действие — цвета текста (`--acc`), фирменный цвет палитры — горячий (`--hot`).

| Палитра | id | Фон | Горячий цвет |
|---|---|---|---|
| Точка (по умолчанию) | `dot` | чёрный | красный |
| Тёплая ночь | `dark-warm` | тёплый графит | жёлтый |
| Студия | `dark-neutral` | холодный графит | жёлтый |
| Глубина | `dark-sea` | тёплый графит | голубой |
| Солнечная | `light-cream` | кремовый | янтарный |
| Бумага | `light-neutral` | белый | красный (светлая «Точка») |
| Зефир | `light-rose` | розоватый | малиновый |

Новые палитры проверять по контрасту: текст ≥ 7:1, приглушённый ≥ 4,5:1, горячий цвет на фоне ≥ 3:1 (значки). Отличия шрифтами и скруглениями владелец пока выдавать не хочет.

Ещё настраивается: акцент (подменяет `--hot` в любой палитре), обои, плотность, форма плеера, полосы распределения денег, оценка быстрого лайка; галерея тем, экспорт и импорт JSON. В текстах не обещать «настраивается всё, вплоть до мелочей» — называть конкретно, что меняется.

## 5. Язык интерфейса

Русский должен читаться естественно для носителя.

- **Тон**: сдержанно-приветливый, тёплый, без сюсюканья и канцелярита.
- **«Медиатека»**, не «Библиотека».
- **Не называть раздел «Поддержка»**: в российских приложениях (VK, «Мой МТС», Яндекс, Boosty, Apple) это служба поддержки. Раздел с деньгами — **«Артистам»**, заголовок — «Кому идут ваши деньги». Глагол «Поддержать» на кнопках — норма (VK Донат, Boosty, Дзен).
- **Без безглагольных калек**, где подлежащее — существительное, а глагола нет: «Поддержка в июне», «Моя поддержка артисту», «пополнение — в два касания». Переписывать через глагол: «Кому идут ваши деньги в июне», «пополнить можно в два касания». Метки над числами («Артистов в июне», «Комиссия сервиса») — нормальная форма.
- **Новые формулировки такого рода сверять с русскоязычными источниками**: словари (Ожегов, Ушаков, Розенталь, Грамота.ру), реальные российские сервисы. Пример: «1 поддержка» — ошибка (в значении помощи только ед. ч., Ушаков); «поддержка артисту» — дательный при самом существительном нормален только в значении «опора» (Розенталь), в «оказать поддержку кому» он у глагола.
- **Чуть более длинная естественная фраза лучше рубленой.**
- **«Комиссия сервиса 0%»** — ровно так.
- Деньги — только через `app.money` (знак валюты перед числом; в RU — с запятой: `money.fmt(1.9)` → `$1,90`, `€1,90`), см. 7.4. Числительные склонять («и ещё 2 артиста»).
- Названия треков и артистов не переводить. Все строки — в `js/i18n.js`, RU и EN.

## 6. Функции и принятые решения

### 6.1. Что есть

Онбординг (манифест → вход Google или фраза-ключ → тема → сумма → три карточки); Главная (виджеты «Вы остановились здесь», «Кому идут ваши деньги в июне», «Что слушают друзья»; ряды); Поиск; Медиатека; Альбом; Артист; Плейлист, Любимые треки, «Показать все», Жанр; Профиль, Jam; «Артистам» (сумма, пополнение, баланс, распределение точками, история); Настройки (Внешний вид, Воспроизведение и загрузки, Оценки, Язык и регион, Подсказки, Аккаунт, Продвинутое); плеер-островок / скруглённый / панель; полный экран; правая панель и очередь; мини-плеер; контекстные меню; уведомления; устройства; донат; загрузки; RU/EN.

Заглушки: «Подробные карточки-инструкции» (ведут в онбординг), «Открыть конфиг» (уведомление), подкасты.

### 6.2. Телефон (Android, ≤640px)

Отдельная раскладка: нижняя навигация (Главная, Поиск, Медиатека, Артистам; повторный тап — наверх, память прокрутки по вкладкам), шапка с логотипом или «Назад» и заголовком страницы при прокрутке (+ маленькая «Слушать»), мини-плеер (капсула или панель; тап — развернуть, свайп вбок — трек, вверх — развернуть; прогресс в капсуле только индикатор), полный экран (обложка/точки, текст и очередь на месте обложки, смахнуть вниз — свернуть, свайп по обложке — трек), строки треков (состояние + «⋯», тап играет, долгое нажатие — меню), нижние листы с ручкой, отклик на нажатие и вибрация.

### 6.3. Лайк и оценка

**Лайк — это оценка.** Источник правды — `rating`: 1–10 или `null`.

- 5–10 — в любимых (сердечко закрашено); 1–4 — «не нравится» (зачёркнуто, `--bad`); `null` — не оценивали.
- Тап по пустому — `likeRating` (настройка «Оценки», 5–10, по умолчанию 10). Тап по горящему — снять; для осознанной оценки (≠ `likeRating`) в тосте «Вернуть».
- Удержание (350 мс) — окно шкалы; не отпуская палец, можно вести: значение и крупная цифра меняются на ходу, отпускание ставит. Без движения (порог 10px) окно остаётся.
- Окно **само не закрывается**: тап мимо, чёрточка сверху, Esc. «Убрать оценку» = `null`.
- В полном экране и в панели плеера шкала встроена (`RateScale variant="inline"`).
- Цифра у сердечка — только для оценки ≠ `likeRating`.
- Лайк без числа (данные из базы, старые сохранения) читается как `likeRating`.

### 6.4. Не меняется без обсуждения

- Сердечко и плюсик — **разные** кнопки.
- Лайк — это оценка (6.3).
- Кнопки в строке трека на компьютере — по наведению, лайк и «скачано» видны всегда; порядок ♥ · ＋ · ⭳ · $. На телефоне — состояние и «⋯».
- Умное перемешивание — третий режим кнопки + уведомление.
- «Медиатека»; раздел «Артистам».
- Форма плеера — настройка.
- Подкасты вторичны.
- Валюта — $ по умолчанию, меняется один раз и запоминается.
- Пополнение — два пути карточками; никакого «автосписания».
- Логотип — «волна голосового» (`docs/logo/`); в прототипе не используется. Запасные значки (`docs/logo/reserve/`) — на далёкое будущее: выбор значка пользователю **не давать**, пока приложение не станет известным.

### 6.5. Ждут решения владельца

Выносилось на одобрение, ответа пока нет. Сделанное по умолчанию одобренным не считать; когда работа касается пункта — спросить. Ответ владельца — перенести в нужный раздел, пункт отсюда убрать.

**Сделано по умолчанию — подтвердить:**
- Плеер: «Повтор» — текущий трек; доиграл — следующий, очередь по кругу; трек начинается с 0:00.
- Плюсик на странице альбома добавляет весь альбом; нажатие на загрузку во время загрузки её отменяет.
- Донат больше баланса — вместо «Отправить» кнопка «Пополнить счёт».
- «Артистам»: цена точки зависит от ширины (на 412 px — 25 центов). Островок прячет «FLAC» от 680 px.
- Валюта: свои деньги — те же числа в выбранной валюте; по курсу-заглушке (EUR 0,92, GBP 0,79) — только доходы артистов и комиссии сети. Знак перед числом и у € и £. Значок `$` у доната и вкладки «Артистам» — не по валюте.
- Настройки: фраза-ключ и поле импорта темы сворачиваются при уходе из раздела.
- Полный экран на компьютере без текста песни: обложка слева, название справа (так было до «Точки»; в «Точке» название стояло под обложкой и ложилось на кнопки). Нижний ряд на узком окне — в два ряда, «Поддержать» местами сжимается до `$` (ступени — в 7.3).
- Суммы: единственная граница — техническая, 13 цифр до запятой (дальше JavaScript не хранит копейки точно, и на экране оказывалось бы другое число). Длинные суммы: на телефоне в «Артистам» уходят строкой ниже полосы, бейдж в сайдбаре — на вторую строку.
- Окно «Пополнить счёт сейчас?» появляется только на «Артистам» (в онбординге нет счёта и окон каркаса).
- Экран ошибки показывает под объяснением строку с текстом ошибки и компонентом (моноширинно, мелко) — чтобы для отчёта хватало скриншота.
- Прототип переехал в корень: демо открывается по `https://alastor1991.github.io/spotless-design/` без перенаправления; старый адрес `/spotless/` ведёт туда же через `404.html`. Ещё короче — только переименовать репозиторий или свой домен (решает владелец).
- Шапка страницы непрозрачная (было 86% с размытием фона): прокрученное просвечивало сквозь неё, а в Slint размытия фона нет.
- Телефон: у альбома и артиста «Поддержать…» — своей строкой во всю ширину, «Поделиться» — только в «Ещё»; у плейлиста и «Любимых» кнопки как у альбома (кольцо 48 px; было — голые значки 42 px). Фильтры медиатеки — лентой с прокруткой. «Вы остановились здесь» — обложка рядом с названием, кнопки одной строкой. В полном экране название — во всю ширину, автор и оценка — строкой ниже.
- Наведение — только для мыши; нажатие — лёгкое сжатие кнопок на всех устройствах; фокус с клавиатуры — обводка цвета текста.
- Новые тексты: «Полосы распределения денег»; «От крупной доли — самая длинная полоса во всю ширину. От всей суммы — вся ширина равна сумме в месяц.»; «От крупной доли»; «От всей суммы»; «Пополнить счёт сейчас?»; «Вы выбрали $X в месяц, а на балансе $Y. Если пополнить счёт на $Z, денег хватит на этот месяц.»; «Пополнить на $Z»; «Не сейчас»; «Что-то пошло не так»; «Этот экран не открылся из-за ошибки в прототипе. Ваши настройки, оценки и плейлисты на месте.»; «На главную»; «Не получилось открыть картинку»; «По запросу «…» ничего не нашлось»; «1 точка = 25 пенсов».

**Не трогал — решать владельцу:**
- Онбординг: на 412×757 кнопка «Далее» на шаге тем ниже экрана; «Пройти знакомство заново» запускает весь онбординг, а подпись обещает «те же три карточки».
- Плеер: перемешивание не меняет порядок; «Предыдущий» и после первых секунд трека сразу переключает, а не возвращает к его началу; трек, включённый из списка, не меняет очередь; играющий трек нельзя убрать из очереди; на телефоне очередь не перетаскивается пальцем, хотя подсказка это обещает.
- Вид: пустые «Скачанное» и очередь — без текста; обои почти не видны под затемнением; на телефоне в мини-плеере скрыта цифра оценки у сердечка — задумано?
- Мелочи: числа прослушиваний обрезаются на 1000 px; в EN плейсхолдер «Custom amoun»; поиск показывает 4 трека без «Показать все»; «Назад» в поиск теряет запрос; «В очередь» для трека, который уже там, пишет «Добавлено»; подсказка `⌘K` в пяти палитрах — контраст 4,2–4,5 (норма 4,5:1).
- Структура: CSS в два слоя (`.x` и `[data-theme] .x` — базовые значения мёртвые, `!important` у h1/h2) — схлопнуть со сверкой снимков; inline-стили — в классы; зелёный «в плюс» `oklch(0.7 0.13 150)` — токеном палитр; убрать мёртвые строки `i18n.js` и `.slider-*` в CSS.

## 7. Устройство кода

### 7.1. Стек

- React 18.3.1 UMD + Babel standalone в браузере. Версии и `integrity` в тегах скриптов не менять.
- Каждый `.jsx` — отдельный `<script type="text/babel">`; общие компоненты отдаются через `Object.assign(window, {...})`.
- Один `css/app.css`: переменные, container queries, без Tailwind.
- Один корневой `App` + контекст `AppCtx` / `useApp()`. Состояние разложено по хукам-разделам в `state.jsx`, `App` (`app.jsx`) склеивает их в один объект `api` — его и читают компоненты (7.4).
- Код должен работать **и без Babel** (живая сборка, раздел 8): `const` до объявления — ошибка.
- **Свежие файлы после выкладки.** GitHub Pages разрешает браузеру 10 минут брать файлы из кэша, а обычное обновление перепроверяет только сам HTML — сразу после выкладки страница собиралась из старых скриптов. Поэтому к адресам файлов прототипа дописывается `?v=` — время выкладки (`document.lastModified`): `app.css`, `data.js` и `i18n.js` подключаются через `document.write` в `index.html`, у тегов `text/babel` скрипт в конце `index.html` дописывает версию **и время открытия**: Babel скачивает их сам и успехом считает только ответ 200 — файл с 304 (Firefox при перепроверке кэша) молча пропускался, и приложение падало на «… is not defined»; если файл не пришёл совсем (Babel и тогда запускает остальные) и до открытия приложения в консоли «Could not load» или «… is not defined», страница один раз перезагружается сама (не чаще раза в 30 секунд). Новый `.jsx` — обычный тег `<script type="text/babel" src="js/…">` в общем списке.

### 7.3. Раскладки и адаптив

- **Телефон**: `useMedia(PHONE_Q)`, `PHONE_Q = "(max-width: 640px)"`. Сайдбар и правая панель не рендерятся; `MobilePlayer` + `MobileNav`; `FullScreenPhone` вместо `FullScreen` (отдельные компоненты — порядок хуков не прыгает). Класс `.shell.phone`, при панели — `.mp-docked`.
- **Компьютер, экстремальное сжатие**: правая панель прячется первой (≤1300px); сайдбар — рейл кнопкой или сам (<1180px); островок — контейнер-запросы, центр `clamp(150px, 40cqi, 460px)`, ступени скрытия: громкость ≤1080 → лайк/плюс/$ ≤980 → значок «FLAC» ≤680 → текст/устройства ≤790 → перемешивание/повтор/очередь ≤545 → время и название ≤400 → prev/next ≤330 (две последние на компьютере недостижимы: ниже 640px — телефонная раскладка); панель плеера — свои ступени, первый отсек в рейле — 248px (`--dk-first`). Ступени с `!important` (inline-стили иначе перебивают).
- **Полный экран на компьютере**: сцена `.fs-grid` — `container-type: size`, обложка `--fs-cover` считается от её размеров; без текста песни — обложка слева, название справа, с текстом — текст под названием, ≤980px обложка прячется. Нижний ряд — ступени: ≤1300 «Поддержать» → `$`; ≤1200 плеер отдельным рядом сверху (подпись возвращается); ≤780 снова `$`; ≤690 загрузка уходит в «Ещё». Раскладка — классами (`.fs-side`, `.fs-info`, `.fs-ctrl-*`), не inline.
- **Короткие экраны телефона**: `.fsp-stage` с `container-type: size`, обложка `max(120px, min(100cqw, 100cqh - 52px))`; ≤800px по высоте прячется строка текста песни, ≤660px — строка о доле; ≤380px по ширине кнопка доната сжимается до `$`. Онбординг — `.ob` из трёх зон в потоке.
- **Плотность** — `data-density="c|n|s"` на `<html>`; правила в конце `app.css`.

### 7.4. Состояние

- **Хуки-разделы** (`state.jsx`): каждый владеет своим куском состояния и возвращает `{ api, keep }` — `api` видят компоненты, `keep` сохраняется между запусками. Связи между разделами — только явные: `App` передаёт `toast`, `hint`, `t`, `go` параметрами. `joinApi` ругается в консоль, если имя в `api` повторилось. Новое состояние — в подходящий раздел (или новый хук), не в `App`.
- `localStorage["spotless_proto_v1"]`, внутри `uiVersion: 2` (старые сохранения один раз переводятся на «Точку»). Читается один раз и проходит `cleanSaved`: id, которых нет в мок-базе, и мусор отбрасываются, остальное не трогается. Меняешь id в `data.js` — сохранения тестеров не ломаются. Пишет `usePersist(keep)`; `saveLS` при переполнении квоты сохраняет всё, кроме картинки обоев.
- `settings`: `island` (`pill` | `square` | `panel`), `density` (`c` | `n` | `s`), `accent`, `wallpaper` / `wallpaperImg`, `likeRating`, `dotScale` (`share` | `total`). Допустимые значения — `cleanSettings` (при загрузке и при импорте темы). Картинка обоев пережимается (`shrinkImage`, 1600 px, JPEG).
- **Прогресс трека** — не в состоянии App, а в хранилище `createProgress` (`app.progress`); читают его только плеерные компоненты через `useProgress()`. Шаг тика — секунда трека; трек доиграл — следующий из очереди, с повтором — тот же сначала.
- **Очередь** крутится по кругу; «Далее» — `upNext(queue, current)` (после текущего, потом с начала). Трека нет в очереди — «следующий» = начало очереди, «предыдущий» = начало трека; пустая очередь — кнопки ничего не делают.
- **Деньги** — `app.money` (`makeMoney(currency, lang)` в `core.jsx`): `fmt(n, keepZeros)`, `num` (без знака), `int` (крупные), `fee` (комиссии сети, 3 знака), `parts` (целые и копейки для крупных цифр), `sign`, `usd(n)` — пересчёт по курсу. Свои деньги человека (сумма в месяц, баланс, донаты, история, чипы сумм) — в его валюте теми же числами: валюту выбирают один раз. По курсу (`DB.currencies`, заглушка) пересчитываются только долларовые суммы сервиса: доходы артистов и комиссии сети. Значок `$` у кнопки доната — значок действия, а не валюта. Литералов `$` в суммах нет. Баланс — `app.balance` (не `DB.balance`: там только начальное значение), меняется только через `topUpBalance(n)` и `payFromBalance(n, name)`, они же пишут историю `app.txs`.
- Суммы из полей ввода — `cleanAmount` (запятая или точка; до запятой не больше 13 цифр — граница точности `AMOUNT_MAX`, не продуктовая) и `parseAmount`, без своих регулярок; крупное число вписывается в ширину виджета через `useFitScale`; обратно в поле — `amountText`. Доля артиста — `splitNow(monthly)` / `shareOf(artistId, monthly)`.
- `trackStates[id] = { rating, liked, playlists }`: читать **только** через `trackState(id)`, менять **только** через `setRating` / `toggleLike` / `patchTrack`. Обновления функциональные: `stateFrom(all, id)` считает из снимка, а не из замыкания.
- Тосты: `toast(msg, action?)`, где `action = { label, run }` — такой тост живёт дольше и показывает кнопку.
- **Окна уходят с анимацией**: `useExit(value)` держит окно ещё `EXIT_MS` после закрытия, с классом `is-out` (нажатия в это время не принимаются). Содержимое уходящего окна — из сохранённого значения (параметр окна), не из `app`: там уже пусто. Ключ окна — `keyOf(цель)`: новый у каждого открытия, состояние («Спасибо», сумма) не переживает закрытие, даже если открыть снова во время ухода.

### 7.5. События и жесты

1. **Поверхность с жестами сама распознаёт тап** (сдвиг < `SLOP` = 10px) и не полагается на всплывающий `click` от детей.
2. **Элементы управления внутри поверхности исключаются по цели**: `e.target.closest("button, [role=slider], .dotbar.seek")`.
3. **Долгое нажатие** — `useLongPress`: только палец, сдвиг > `SLOP` — прокрутка; клик при отпускании пальца гасится **где угодно** (`swallowReleaseClick`): меню всплывает листом под пальцем; на сенсорных устройствах нативный `contextmenu` гасится (`isTouchUI()`).
4. **Окна над прокручиваемым контентом** — портал в `body` + граница событий на корне (`stopPropagation` на pointer- и click-событиях): события портала всплывают по дереву React. Так устроены `RatingPop` и поповер плюсика `PlusPop` (он ещё и открывается вниз, если сверху нет места). Модальные окна — общий `Sheet` (`ui.jsx`): тоже портал, затемнение на всё окно, ручка на телефоне, Esc (`useEscape`).
5. **«Клик мимо»** — слушатель на `window` в фазе перехвата (`addEventListener(..., true)`); исключать сам поповер и якорь.
6. **Сердечко** — машина состояний `press → armed → scrub` с `setPointerCapture`; шкала — общий `RateScale` (палец, мышь, клавиатура, `onPreview` для живой цифры).
7. Элементы с жестами — `touch-action: none`; списки внутри — `pan-y`; прокрутка — `overscroll-behavior: contain`.
8. Перед жестом, двигающим элемент с анимацией появления, доиграть её: `finishAnims(el)`. Не `animation: none` — инлайн-«none» потом не дал бы сыграть уходу.
9. Вибрация — `buzz(ms)`, молча ничего, если нельзя.
10. Подсветка по наведению — классами в `app.css`, внутри `@media (hover: hover)` (на телефоне она залипала после касания), не `onMouseEnter`/`onMouseLeave` в компонентах. Нажатие (`:active`) — для всех; у пальца строки и пункты меню ещё и подсвечиваются.
11. **Лента треков** (мини-плеер, обложка полного экрана) — `[предыдущий | текущий | следующий]` (`nearTracks`): идёт за пальцем 1:1, соседа видно сразу; отпустил дальше трети или рывком — доезжает со скоростью пальца (`stripRelease`, `fling`), иначе возвращается (`stripBack`, `--ease-settle`). Смена трека кнопками или сама — та же лента с нужной стороны (`useStripSync`); трек не по соседству (включили из списка) — проявляется. Кнопки капсулы не двигаются.
12. Окна и меню ставим от `boxOf(кнопка)`, а не от `getBoundingClientRect`: нажатая кнопка сжата (`:active`), и окно съезжало на пиксель.

## 8. Живая сборка для артефакта

Владелец удобнее всего тестирует на телефоне через артефакт Claude. Просмотрщик артефактов ставит свой `data-theme` на корень и требует скриптов с разрешённых CDN, поэтому:

1. JSX компилируется заранее esbuild-ом (`--loader=jsx --jsx=transform --target=es2020`, вход через stdin) в обычные `.js`, порядок файлов как в `index.html`.
2. `data-theme` в CSS и JS переименовывается в `data-sp-theme`.
3. Страница артефакта — без `<!doctype>/<html>/<head>/<body>` (их добавит публикация): `<title>`, ссылка на Google Fonts (как в `index.html`), `css/app.css`, `<div id="root">`, React и ReactDOM 18.3.1 production с cdnjs, затем скрипты.
4. Публикация — многофайловым артефактом (`files`: `css/app.css`, `js/*.js`), повторная публикация — тот же путь файла, ссылка сохраняется.
5. После сборки — те же проверки (раздел 9) на собранной версии.

```sh
mkdir -p out/js out/css
# список и порядок файлов — из index.html, чтобы не расходились
for f in $(grep -o 'src="js/[a-z-]*\.jsx"' index.html | sed 's/src="js\///; s/\.jsx"//'); do
  npx esbuild --loader=jsx --jsx=transform --target=es2020 < js/$f.jsx | sed 's/data-theme/data-sp-theme/g' > out/js/$f.js
done
cp js/data.js js/i18n.js out/js/
sed 's/data-theme/data-sp-theme/g' css/app.css > out/css/app.css
```

## 9. Проверка

Каждая партия изменений — **в трёх браузерах владельца**, без ошибок в консоли: Chromium через Playwright (предустановлен, `playwright install` не нужен); **Яндекс Браузер** — пакет с repo.yandex.ru, распаковать `dpkg-deb -x`, запускать тем же Playwright (`executablePath`, `--no-sandbox`); **Firefox** — `npx @puppeteer/browsers install firefox@stable` и `puppeteer-core` (WebDriver BiDi), прокси — через `extraPrefsFirefox`. Проверка только в Chromium пропустила баги, которые владелец ловил в Яндексе и Firefox. Firefox без экрана (headless) сообщает `(hover: none)`, и прототип считает его сенсорным — нет меню по правому клику и подсветки наведения; как у настоящего Firefox с мышью — настройки `ui.primaryPointerCapabilities` и `ui.allPointerCapabilities` = `6` в `extraPrefsFirefox`. Сертификат прокси — в профиль, копией `~/.pki/nssdb`. После выкладки — те же проверки на живом демо.

- **Размеры**: компьютер 1440×900, 1280×800, 1000×800, 700×800; телефон **412×806** (Nothing Phone (3a) Lite в Chrome, коэффициент 2,625), 412×915, **412×757**, 360×640.
- **Касания — настоящие** touch-события через CDP: `cdp.send('Input.dispatchTouchEvent', { type: 'touchStart' | 'touchMove' | 'touchEnd', touchPoints })`. Клики мышью не ловят ошибки жестов.
- **Лайк и оценка (обязательно)**: быстрый тап ставит `likeRating` и не разворачивает мини-плеер; кнопка не прыгает; удержание с дрожанием 3px не ставит оценку и не закрывает окно; ведение меняет крупную цифру на ходу; тап по точкам ставит и правит, окно не закрывается само; чёрточка и тап мимо закрывают; «Убрать оценку» гасит сердечко; тап по горящему снимает, «Вернуть» возвращает; `likeRating: 7` → тап ставит 7; на компьютере — удержание мышью, клик по точке, правый клик по строке.
- **Жесты**: свайпы мини-плеера, смахивание полного экрана и листов, долгое нажатие на строке (строка должна быть в видимой области — мини-плеер перекрывает низ), заголовок в шапке при прокрутке.
- **Полный экран на компьютере** — в обоих режимах (с текстом песни и без) на всех размерах: название, кнопки и таймкод не наезжают друг на друга, нижний ряд целиком в окне.
- Одна из старых тем (например, «Солнечная») не сломана.
- **Крупные правки (рефакторинг, улучшение структуры, оптимизация) — обязательно с доказательством, что ничего не сломалось и не появилось новых багов.** До правок — эталон: снимки ключевых состояний (страницы, окна, меню, онбординг, телефон, темы, размеры) при остановленных часах (`page.clock`) и постоянном `Math.random`; два прогона эталона должны совпасть. После — те же снимки и попиксельное сравнение: каждое отличие объяснить (намеренное — назвать в отчёте, остальное — чинить). Плюс проверки поведения и сценарии через переделанные части — на исходной и собранной версии. Скрипты — во временной папке, в репозиторий не класть.
- На настоящем телефоне последнее слово за владельцем: эмуляция не передаёт ощущение жестов и вибрации.

## 11. Будущая реализация и право

Контекст для текстов: экраны и формулировки не должны этому противоречить. Это контекст, а не задание: ничего из этого не писать — ни в прототипе, ни отдельно (главное правило в начале файла).

- **Клиент на компьютере** — Rust + **Slint** (декларативная разметка переносит CSS-переменные тем в Slint-глобалы почти один в один, API стабилен с 1.0; GPL-вариант совместим с AGPL). Сначала Linux (Flatpak), потом Windows. WebView (Tauri, Electron) исключён: клиент должен быть лёгким. Выбор подтверждён сравнением стеков (октябрь 2026). Фонового размытия в Slint (1.18) нет.
- **Телефоны** — свой нативный интерфейс на каждой платформе: Android — Kotlin + Jetpack Compose, iOS — SwiftUI (там настоящий Liquid Glass). Общие у всех — Rust-ядро и токены дизайна. **Telegram Mini Apps отменены.**
- **Граница фронта и ядра (решение владельца):** шторка плеера и системные кнопки воспроизведения — фронтенд; воспроизведение звука — бэкенд; откуда интерфейс берёт настоящий прогресс прослушивания — владелец решит, когда возьмётся за бэкенд. До тех пор везде заглушки.
- **Ядро**: rust-libp2p, symphonia + cpal, некастодиальный кошелёк, проверка чанков, локальная база.
- **Инфраструктура** — Go (пишет владелец): bootstrap/relay-ноды, индексатор каталога, кабинет артиста. Контент на серверах не хранится.
- **Деньги** — Solana, контракты Rust / Anchor, актив **USDC**; распределение — накопление в контракте и выплаты пачками; комиссию сети платит fee payer, слово «газ» пользователь не видит.
- **Фиат** — он-рамп-провайдеры (Onramper или MoonPay / Ramp / Mercuryo), Apple Pay, Google Pay, карта, SEPA; KYC у провайдера, один раз; подписочного API нет → напоминание.
- **Право**: архитектура строго некастодиальная (проект не держит ключи и средства) — вне CASP по MiCA и money transmitter по FinCEN, пока это так; любая «централизованная» функция проверяется на этот инвариант. KYC только на границах фиат ↔ крипта у лицензированных провайдеров. В текстах — никаких обещаний из области права («анонимно», «никогда не потребуют»), только факты про наш интерфейс («не понадобится»).
